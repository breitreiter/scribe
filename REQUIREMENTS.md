# Scribe - Requirements

## What We're Building
Scribe is a handy tool for generating a nice report from a video or audio recording of a meeting.

## Core Workflow
- User supplies an audio file. If scribe is called without parameters, instead ask the user for the path to the audio file.
- Verify that the file exists and can be read. If not, display an error and exit.
- Verify that scribe has all required configuration settings. If not, error and exit.
    - Model connectivity info
    - By default, scribe ships with an appsettings.example.json. If appsettings.json doesn't exist, we should prompt the user to copy and edit the template file.
- Ask the user for the number of speakers
- Ask the user to provide a title for the meeting
- Ask the user to provide the purpose or structure of the meeting (presentation, daily stand-up, etc)
- Create a new directory using the sanitized/truncated (100 char) title of the meeting
    - Resolve collisions by adding a numerical index
    - Copy the audio file to the new directory
- Send the file to an AI for transcription. For now, just Azure OpenAI Whisper. 
- Walk the user through assigning a nice name to each of the speakers identified by Whisper.
    - Explain that we've identified [total] distinct speakers, and we need the user's help to identify them
    - Loop through each speaker
        - Note that we're looking for the identity of speaker [index]
        - Display the first line spoken by the user with the timestamp of that line
        - If the first line was very short, show another line with timestamp. Repeat until you've shown at least 20 words from that speaker or 3 lines. 
        - If any line would overflow the width of the console, just truncate it. Use something like line.substring(console.width - 4) + "..." or whatever.
        - Ask the user for the name of this speaker
        - If the user declines to provide a name, keep the name generated by Whisper
- Tidy up the transcript so it reads more like a play dialogue. 
    - By default, Whisper groups lines by speaker and creates very fragmentary lines
    - Instead, we want to show lines from different speakers interleaved, in the order they were spoken
    - We also want to concatenate multiple short lines from the same speaker into larger speech blocks
- Use an AI to add labels to the conversation to mark changes in topic. For now, just use Azure OpenAI o4-mini
- Use an AI to add a short preamble to the top of the transcript, using the meeting title and purpose
- Use an AI to generate a concise (but complete) summary of the meeting. 
    - Use the meeting purpose supplied by the user to make good decisions on how to write the report.
- Write the transcript and summary (two files) to the new directory we created
- Output a short summary of work done and a reminder of where the files were created

## Technical Notes
- Tech stack: C# / .NET
- Spectre Console for nice UI
- Logging: Serilog to file (loosely coupled - easy to remove if we hate it)
  - Log to `scribe.log` in the per-run output directory
  - Default level: Warnings and Errors only (configurable in appsettings.json)
  - Delete log file at end of run if empty (no noise when everything works)
  - Keep console clean for Spectre output
  - Consider adding `--verbose` flag later for debug-level console logging
- External dependencies: Azure OpenAI, possibly more providers in the future.
- Audio format support: Whatever Whisper supports (mp3, mp4, mpeg, mpga, m4a, wav, webm)
- Output structure:
  - Create directory based on user-supplied meeting title (sanitized for filesystem)
  - Max directory name length: 100 characters
  - Resolve collisions by appending numerical index (-2, -3, etc.)
  - Directory contains: transcript.md, summary.md, and copy of original audio file
  - AI generates preamble using user-supplied title and purpose (not generating the title itself)
- Configuration structure:
  - Check for appsettings.json at startup; if missing, prompt user to copy from appsettings.example.json
  - Keep provider settings separate (don't cluster Whisper + o4-mini even though both Azure OpenAI)
  - Design for multiple provider support in the future
  - Settings needed: API endpoints, keys, deployment/model names for each AI service
  - appsettings.json is gitignored; ship appsettings.example.json as template
  - Separate sections: Transcription (Whisper) and Completion (o4-mini)
